# ApkPy 1.12.1 — a comparison between two values

Write native Android apps in the supported Python subset. The generated APK
still contains Java/XML, not a Python runtime.

One fix, and nothing else changed from 1.12.0.

```
python -m pip install --upgrade apkpy==1.12.1
```

## What was wrong

```python
def check():
    if password.get_value() == again.get_value():
        toast("They match")
```

At the desk this did what it says. On the phone it asked whether the first
field was empty.

In an `if` or an `elif`, the right side of a comparison reached the phone
only when it was written out in the source, like `"abc"` or `3`. A name, a
field's value, the answer of a call, a sum, a number below zero or a name
defined at the top of the file became empty text, and the build said
nothing. The Previewer runs your Python and always answered correctly, so
the two disagreed only on a phone. It has been so since at least 1.8.0.

| You wrote | On the phone, up to 1.12.0 | 1.12.1 |
| --- | --- | --- |
| `if a == b:` | true only when `a` was empty | true when the two are the same |
| `if a != b:` | true whenever `a` was not empty | true when they differ |
| `if i < n:` | never true | compares the two numbers |
| `if n > -1:` | true whenever `n` held anything | compares the two numbers |
| `while i < n:` | compared as text: stopped at 2 when `n` was 12 | compares the two numbers |
| `if name == "Ana":`, `if count > 3:` | right | unchanged |

## Upgrading

- Install 1.12.1 and build the app again. The fix is in the build: an APK
  made by an older version keeps the old answer until it is rebuilt.
- An app that only compared against values written in the source is built
  into exactly the same files as before.
- An `if` between two values can now be true where it never was. Read what
  its branch does before you ship: it may be running for the first time.
- What somebody typed in a field is text until `int(...)` makes it a number:
  `int(a) < int(b)`, not `a < b`.
